# Зерттеу: жеке кабинетке кіру тәсілдері (eGov.kz мысалында)

## 1. Зерттеудің мақсаты

Әзірлеуді бастамас бұрын Қазақстанның электрондық үкімет порталы eGov.kz-тегі кіру жүйесі зерттелді. Жобаның міндеті: Java тілінде кіруге арналған үш тәсілі бар жеке кабинет жасау:

1. телефон нөмірі арқылы (бір реттік SMS-код);
2. ЭЦҚ (электрондық цифрлық қолтаңба) арқылы;
3. QR-код арқылы.

## 2. eGov.kz-те кіру қалай жұмыс істейді

Порталда авторизацияның бірнеше тәсілі бар. Олардың ішінде eGov Mobile қосымшасындағы QR-код арқылы кіру және ЭЦҚ арқылы кіру бар.

2025 жылдың қазан айынан бастап ЭЦҚ арқылы кіру екі кезеңді болды: алдымен пайдаланушы кілтті растайды, содан кейін 1414 нөмірінен SMS арқылы келетін бір реттік кодты енгізеді. SMS тек телефон нөмірі есептік жазбаға байланған жағдайда ғана келеді.

## 3. Қазақстандағы ЭЦҚ қалай жұмыс істейді

- Кілттерді Қазақстан Республикасының Ұлттық куәландырушы орталығы (ҰКО) береді.
- Бұрын азамат екі кілт алатын: AUTH RSA (кіру үшін) және RSA (құжаттарға қол қою үшін).
- 2024 жылғы 28 сәуірден бастап ҰКО СТ РК ГОСТ Р 34.10-2015 алгоритміндегі бір кілт береді, ол кіру үшін де, қол қою үшін де қолданылады. Бұрын шығарылған кілттер мерзімі біткенше жұмыс істейді.
- Браузерде кілттермен NCALayer бағдарламасы жұмыс істейді: ол веб-сайт пен кілт файлын немесе токенді байланыстырады.
- Ақпараттық жүйелер сертификаттардың күшін жоюын CRL және OCSP сервистері арқылы тексереді.

### Жоба үшін қорытынды

Нақты ҰКО ЭЦҚ-сын оқу жобасына қосу мүмкін емес: нақты кілттер, NCALayer және сенімді сертификаттар қажет. ГОСТ 2015 алгоритмі стандартты JCA кітапханасына кірмейді. Сондықтан жобада өз сынақ куәландырушы орталығы бар **RSA негізіндегі ЭЦҚ имитациясы** жасалады. Жұмыс принципі сақталады: сервер кездейсоқ сынақ (challenge) жібереді, клиент оны жабық кілтпен қол қояды, сервер қолтаңбаны сертификаттағы ашық кілтпен тексереді.

## 4. Үш кіру тәсілін салыстыру

| Өлшем | Телефон + SMS | ЭЦҚ | QR-код |
|---|---|---|---|
| Тұлғаны не растайды | Нөмірге иелік ету | Жабық кілтке иелік ету және құпиясөзді білу | Авторизацияланған құрылғының кіруі |
| Негізгі қауіп | SMS-ті ұстап алу, SIM-картаны алмастыру | Кілт файлын ұрлау | QR-ды алмастыру, фишинг |
| Қорғаныс | Кодтың қысқа мерзімі, әрекет шектеуі, кодтың хэші | Қолтаңба мен сертификат мерзімін тексеру, бір реттік challenge | Қысқа мерзімді бір реттік токен |
| Іске асыру күрделілігі | Төмен | Жоғары | Орташа |

## 5. Жобадағы жұмыс сызбалары

### Телефон нөмірі арқылы кіру
1. Пайдаланушы нөмірді енгізеді.
2. Сервер 6 таңбалы код жасайды, оның хэшін (BCrypt) 3 минуттық өмір сүру мерзімімен сақтайды.
3. Нақты SMS орнына код сервер консоліне шығарылады.
4. Пайдаланушы кодты енгізеді. Көбі 3 әрекетке рұқсат етіледі.
5. Сәтті болса, сессия жасалады.

### ЭЦҚ арқылы кіру
1. Клиент challenge сұратады, сервер кездейсоқ байттар қайтарады және оларды есте сақтайды.
2. Клиент challenge-ке PKCS12 сақтауышындағы жабық кілтпен қол қояды (SHA256withRSA).
3. Сервер сертификат тізбегін, әрекет ету мерзімін және қолтаңбаны тексереді.
4. Challenge бір реттік: тексеруден кейін ол жойылады.
5. Сәтті болса, сессия жасалады.

### QR-код арқылы кіру
1. Сайт серверден бір реттік токен сұратады және оны QR-код түрінде көрсетеді.
2. Авторизацияланған құрылғы («телефон») осы токенмен растау жібереді.
3. Кіру беті токен күйін (күтуде, расталды, мерзімі өтті) мерзімді түрде тексеріп тұрады.
4. Расталғаннан кейін сессия жасалады. Токен 1–2 минут өмір сүреді және бір рет қана қолданылады.

## 6. Таңдалған технологиялар

| Мақсаты | Технология |
|---|---|
| Тіл және құрастыру | Java 17, Maven |
| Веб-сервер | Spring Boot |
| Криптография | JCA (`java.security`, `javax.crypto`), `keytool` |
| Кодтарды хэштеу | BCrypt |
| QR жасау | ZXing |
| Тесттер | JUnit 5 |

## 7. Қауіпсіздік шаралары

- Құпия деректер (кілттер, құпиясөздер, `.env`) репозиторийге түспейді (`.gitignore`).
- Барлық бір реттік деректердің (OTP, challenge, QR-токен) өмір сүру мерзімі бар және олар бір рет қана қолданылады.
- Кодтар тек хэш түрінде сақталады.
- Әрекет санын шектеу және іріктеп табуда уақытша бұғаттау.
- Токендер `SecureRandom` арқылы жасалады.

## 8. Жобаның шектеулері

- SMS жіберілмейді, код консольге шығарылады.
- ЭЦҚ ГОСТ 2015 емес, RSA негізінде имитацияланады, ҰКО CRL/OCSP арқылы тексеру жоқ.
- Жоба оқу мақсатында жасалған және өнеркәсіптік қолдануға арналмаған.
